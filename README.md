# AI-Based Intrusion Detection System (IDS)

## Executive Overview

An **AI-Based Intrusion Detection System (IDS)** built using **Python 3.11**, **Django 4.2**, and **Scikit-learn**. This academic system evaluates network traffic flows using a trained **Random Forest Classifier** model trained on the benchmark **UNSW-NB15** dataset to classify network activity as **Normal Traffic** or **Attack (Intrusion)**.

> **Academic Project Notice:** Safe local monitoring and demonstration. No external attack injection, hardware modification, or destructive payload execution is performed.

---

## System Architecture & Data Flow

```
User
  ↓
Django Web Application
  ↓
Authentication / Dashboard / Detection / History / Analytics
  ↓
Live Monitor Demonstration (/live-monitor/)
  ↓
Fixed Demonstration Feature Vector
  ↓
Feature Adapter (42 UNSW-NB15 Features)
  ↓
Preprocessor (188 Expanded Features)
  ↓
Random Forest Classifier (final_model.joblib)
  ↓
Normal / Attack Prediction + Confidence %
  ↓
PredictionHistory Database Persistence
  ↓
Dashboard & Analytics Statistics
```

## Core Features & Modules

### 1. Unified Live Monitoring (`/live-monitor/`)
The application provides a demonstration interface at `/live-monitor/`. It does **not** capture packets, inspect a network interface, or measure live network traffic. Its polling endpoint evaluates fixed sample feature vectors and stores the resulting predictions.
- **Demonstration Dashboard:** Displays monitoring UI state, selected demonstration mode, request client address, last checked timestamp, and evaluations completed.
- **Auto-Start UI:** The browser starts the demonstration polling loop when the page loads.
- **START & STOP Interactive Controls:**
  - **`▶️ Start Monitoring`:** Starts the browser's four-second demonstration polling loop.
  - **`⏸️ Stop Monitoring`:** Stops that browser polling loop; it does not stop or start a packet-capture process.
- **Normal and Attack Demonstrations:** The endpoint selects fixed normal or attack-simulation feature vectors for model inference.
- **Prediction Event List:** Displays recent saved demonstration predictions.
- **No Real Capture:** Results should not be interpreted as observations of actual network traffic.

### 2. Manual Intrusion Detection (`/detect/`)
- Allows security analysts to submit custom 42-feature network flow dictionaries or load pre-filled validation presets (`Normal` or `Attack`).
- Executes validation through `IntrusionPredictor` and displays predictions with confidence scores and probability metrics (`prob_normal` / `prob_attack`).

### 3. User Dashboard (`/dashboard/`)
- Summary card overview showing Total Predictions, Attacks Detected, Normal Traffic, Threat Percentage %, Normal Percentage %, and 5 recent detection events for the authenticated user.

### 4. Prediction Analytics & Reports (`/analytics/`)
- **Attack Type Breakdown:** Grouped percentages of classified threat categories.
- **Time-Based Activity:** 7-day daily activity time-series statistics (`TruncDate`).
- **Model Confidence Analysis:** Average confidence percentage across all predictions.

### 5. Prediction History & Management (`/history/`)
- Complete historical record of all predictions generated by the user.
- **Individual Record Deletion:** POST endpoint `/history/<int:record_id>/delete/` with ownership validation.
- **Bulk History Clear:** POST endpoint `/history/clear/` clearing all records belonging to `request.user`.

### 6. Authentication & User Isolation
- Session-based authentication via Django `contrib.auth` with PBKDF2 SHA-256 password hashing.
- Route protection using `@login_required(login_url='detector:login')`.
- **Strict User Isolation:** All database queries (`PredictionHistory.objects.filter(user=request.user)`) enforce zero data leakage between user accounts.

### 7. Security & Error Diagnostics
- **CSRF Protection:** CSRF token verification enforced across all POST endpoints.
- **Custom Error Pages:** Dedicated user-friendly `404.html` (Page Not Found) and `500.html` (Server Error) templates.
- **Honest Error Diagnostics:** Clear user notifications if live evaluation dependencies fail.

## Machine Learning Pipeline & Dataset

### Dataset Specification
- **Dataset:** **UNSW-NB15** (University of New South Wales Network-Based Intrusion Detection Dataset).
- **Raw Features Input:** 42 network flow attributes (`dur`, `proto`, `service`, `state`, `spkts`, `dpkts`, `sbytes`, `dbytes`, `rate`, `sttl`, `dttl`, `sload`, `dload`, `sloss`, `dloss`, `sinpkt`, `dinpkt`, `sjit`, `djit`, `swin`, `stcpb`, `dtcpb`, `dwin`, `tcprtt`, `synack`, `ackdat`, `smean`, `dmean`, `trans_depth`, `response_body_len`, `ct_srv_src`, `ct_state_ttl`, `ct_dst_ltm`, `ct_src_dport_ltm`, `ct_dst_sport_ltm`, `ct_dst_src_ltm`, `is_ftp_login`, `ct_ftp_cmd`, `ct_flw_http_mthd`, `ct_src_ltm`, `ct_srv_dst`, `is_sm_ips_ports`).
- **Preprocessing Expansion:** `preprocessor.joblib` applies One-Hot Encoding for categorical features (`proto`, `service`, `state`) and standard scaling, expanding feature space to **188 features**.
- **Model Architecture:** **Random Forest Classifier** (`n_estimators=100`, `random_state=42`) loaded from `ml/artifacts/final_model.joblib`.

## Setup & Execution Guide

### 1. Requirements
- Python 3.11+
- Django 4.2.16
- Scikit-learn 1.5.2, Pandas 2.2.3, NumPy 1.26.4, Joblib 1.4.2

### 2. Quick Start
```powershell
# Create your local environment file (do not commit it)
Copy-Item .env.example .env
# Edit .env and replace SECRET_KEY with a private value.

# Install dependencies
pip install -r requirements.txt

# Run migrations
python manage.py migrate

# Execute test suite
python manage.py test

# Start development server
python manage.py runserver
```

Open browser at [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Create your own account using the Register page; no default user or administrator accounts are provided. The sample `.env.example` enables `DEBUG` for local development and uses localhost hosts. Keep `.env` private and never commit it.

### Dataset download and preparation

The dataset is not included in this repository. Obtain UNSW-NB15 from the [official UNSW-NB15 project page](https://research.unsw.edu.au/projects/unsw-nb15-dataset), review its current terms before downloading or redistributing it, and place `UNSW_NB15_training-set.csv` and `UNSW_NB15_testing-set.csv` under `datasets/raw/`. Then run:

```powershell
python datasets/prepare_dataset.py
python ml/preprocessing.py
```

These scripts create local dataset splits and preprocessing artifacts. Training and evaluation scripts are also provided under `ml/`; running them can regenerate or overwrite model artifacts, so they are not required for normal application startup.

For inference, the application requires `ml/artifacts/final_model.joblib` and `ml/artifacts/preprocessor.joblib`. The model metadata file is useful documentation, but is not loaded by the application.
